# Two-Party Secret Sharing Addition

## 1. 功能简介

本模块实现了一个基于**加法秘密共享（Additive Secret Sharing）**的两方安全加法协议，运算环为 **Z_(2^l)**。

其中：
- `l` 为比特长度 `bitlen`
- `bitlen` 的取值范围为 `[1, 64]`

该实现支持以下功能：

- 将某一方的私有输入秘密共享给两方；
- 在共享态下对两个秘密值进行加法运算；
- 将加法结果恢复为明文并返回给双方；
- 支持不同 bit 长度下的模 `2^l` 运算。

---

## 2. 协议原理

对于秘密值 `x`，将其拆分为两个 share：

`x = x0 + x1 (mod 2^l)`

其中：
- Party 0 持有 `x0`
- Party 1 持有 `x1`

单独任意一方都无法恢复 `x`，只有双方将 share 相加才能得到原值。

### 2.1 输入共享

若某一方持有私有输入 `x`，则该方随机生成一个值 `r`，并计算：

`other = x - r (mod 2^l)`

随后：
- 自己保留 `r`
- 将 `other` 发送给另一方

这样两方共同持有 `x` 的加法秘密共享。

### 2.2 共享态加法

若：

`x = x0 + x1 (mod 2^l)`

`y = y0 + y1 (mod 2^l)`

则：

`x + y = (x0 + y0) + (x1 + y1) (mod 2^l)`

因此，共享态下的加法只需要双方分别对本地 share 做加法，不需要额外通信。

### 2.3 结果恢复

设结果 share 为：

`z = z0 + z1 (mod 2^l)`

双方交换各自持有的 share，并相加即可恢复明文结果。

## 3. 模块结构

本实现包含以下两个核心部分：

### 3.1 `ArithShare`

用于表示一个算术秘密共享值，包含：

- `value`：当前参与方持有的 share 数值
- `bitlen`：该 share 所属环的比特长度

该结构是模块中最基本的数据表示形式。

### 3.2 `TwoPartySSAdd`

协议核心类，封装了两方安全加法协议的主要逻辑。

主要成员包括：

- `lctx_`：YACL 通信上下文，用于两方消息收发
- `bitlen_`：运算环比特长度
- `mask_`：对应 `bitlen_` 的掩码，用于实现模 `2^l` 运算

## 4. 核心功能模块介绍

### 4.1 环上基础运算

类中提供了三个静态函数用于环上运算：

- `RingMask(bitlen)`  
  生成对应 bit 长度的掩码；

- `AddMod(a, b, bitlen)`  
  计算模 `2^l` 加法；

- `SubMod(a, b, bitlen)`  
  计算模 `2^l` 减法。

这些函数用于保证所有数值始终落在 `Z_(2^l)` 环内。

### 4.2 `ShareInput`

该函数用于将某一方持有的私有输入转换为两方加法秘密共享。

特点：

- 双方都需要调用该函数；
- 只有输入拥有方真正提供明文输入；
- 非拥有方只负责接收 share；
- 最终双方分别得到一个 `ArithShare`。

### 4.3 `Add`

该函数用于在共享态下执行加法。

特点：

- 不需要通信；
- 仅对本地 share 做模加；
- 返回结果 share。

这是加法秘密共享最核心的性质之一：**明文加法可以转化为 share 的本地加法**。

### 4.4 `RevealToAll`

该函数用于将共享值恢复为明文，并将结果返回给双方。

特点：

- 双方都需要调用；
- 双方交换各自持有的 share；
- 本地求和后得到最终结果。

### 4.5 辅助函数

- `CheckTwoPartyOrThrow()`  
  检查当前通信环境是否合法，例如：
  - `bitlen` 是否在 `[1, 64]`
  - 通信上下文是否为空
  - 当前协议是否确实为两方协议

- `PackU64()` / `UnpackU64()`  
  用于 `uint64_t` 与 `yacl::Buffer` 之间的序列化和反序列化，便于网络传输。
